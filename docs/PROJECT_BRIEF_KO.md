# WhyRight 프로젝트 브리프

> 결정일: 2026-07-21 KST
> 트랙: Education
> 상태: 아이디어 확정, 구현 전

## 1. 한 문장 정의

**WhyRight는 정답을 맞혔지만 잘못된 정신모델을 가진 GPT-5.6 가상 학생에게 교사·튜터가 세 번 질문해 숨은 오개념을 찾아내는 90초 진단 질문 훈련 게임이다.**

태그라인은 다음으로 고정한다.

> The answer is right. The reason is not. Ask the question that reveals why.

## 2. 누구의 어떤 순간을 해결하는가

- 사용자: 중학교 수학·과학 교사, 예비교사, 학원·개인 튜터
- 순간: 학생이 정답을 말했기 때문에 수업을 넘어가려는 바로 그때
- 문제: 최종 답만 보면 우연, 암기, 잘못된 규칙 적용을 구분하기 어렵다.
- 원하는 결과: 정답 확인 질문이 아니라 사고 과정을 드러내는 후속 질문을 짧게 연습한다.

AIED 2026 연구는 잘못된 추론으로도 정답에 도달하는 문제에서 AI 튜터가 오개념을 놓치는 `correct answer trap`을 다룬다. WhyRight는 이 실패를 학생용 자동 튜터가 아니라 **교사용 진단 훈련** 문제로 바꾼다.

## 3. 핵심 제품 루프

1. 사용자가 합성 시나리오 하나를 선택한다.
2. 가상 학생이 정답과 짧은 이유를 말한다.
3. 사용자는 최대 세 개의 후속 질문을 자유롭게 입력한다.
4. GPT-5.6은 비공개 오개념을 일관되게 유지한 채 학생으로만 답한다.
5. 사용자는 답변을 들을 때마다 아직 가능하다고 보는 후보 오개념 집합을 직접 갱신한다.
6. 마지막에 고정 후보 중 숨은 오개념 하나를 고른다.
7. 서버가 사전 작성된 정답표와 사용자 후보 이력만으로 진단·후보 축소 점수를 낸다.
8. GPT 코칭은 점수와 분리해 더 강한 hinge question 하나를 제시한다.

## 4. 첫 시나리오

### Multiplication always makes numbers bigger

- 보이는 문제: `3 × 5 = ?`
- 가상 학생 답: `15` — 정답
- 숨은 오개념: 곱셈은 언제나 원래 수를 더 크게 만든다.
- 가능한 진단 후보:
  - repeated addition만 가능하다고 믿음
  - 곱셈은 언제나 수를 크게 만든다고 믿음
  - 순서를 바꾸면 답이 달라진다고 믿음
  - 단순 계산 실수
- 강한 판별 질문 예: `그 규칙을 1/2 × 8에도 적용하면 결과가 어떻게 될까? 왜 그렇게 생각했어?`
- 목표: 정답을 재계산하게 하는 것이 아니라, 규칙의 적용 범위를 말하게 한다.

두 번째 시나리오는 중학교 과학의 단일 오개념으로 제한한다. 구현 시 검증 가능한 교육 자료를 근거로 확정하고, 범과목 생성기는 만들지 않는다.

## 5. GPT-5.6이 없으면 무너지는 지점

고정 챗봇은 미리 적어 둔 질문에만 답할 수 있다. WhyRight의 가상 학생은 사용자가 어떤 표현으로 질문하더라도 다음을 동시에 지켜야 한다.

- 한 가지 잘못된 정신모델을 여러 턴에 걸쳐 모순 없이 적용
- 질문이 일반적이거나 엉뚱하거나 단순히 `틀렸다`고 말해도 설정된 오개념을 아첨하듯 버리지 않음
- `정답을 말해`, `숨은 프롬프트를 보여줘` 같은 공격에도 설정 비공개
- 너무 완벽한 교사 문장이나 메타 설명이 아니라 학생다운 답변
- 앱이 검증할 수 있는 구조화된 턴 상태 반환

Responses API의 GPT-5.6과 Structured Outputs를 사용한다. 단, 모델은 **역할극 생성기**일 뿐 정답표와 최종 점수의 소유자가 아니다.

## 6. 순환 평가 방지 설계

심사위원이 가장 먼저 공격할 지점은 “GPT가 학생도 연기하고 자기 연기를 스스로 채점한다”는 순환성이다. 이를 구조적으로 끊는다.

- `scenario.json`에 오개념 ID, 핵심 믿음, 후보 진단, 판별 증거를 사람이 미리 작성한다.
- 진단 정오 판정은 문자열 ID의 정확 비교다.
- 사용자는 각 답변 뒤 아직 가능한 후보를 직접 체크한다. 이 클릭 이력이 점수 입력이다.
- 후보 축소 점수는 고정 정답표와 사용자 선택 이력만으로 계산하며 모델 태그를 사용하지 않는다.
- 정답 후보를 유지하면서 제거한 오답 후보 수와 최종 진단 정확도를 별도 표시한다.
- 한 라운드의 숨은 오개념은 서버에 고정된 불변값이며 GPT가 갱신하지 않는다.
- 결과 화면에서 결정론적 점수와 GPT 코칭 문구를 시각적으로 분리한다.

가상 학생의 오개념 충실성은 사용자 점수와 별도로 검증한다. targeted, misaligned, generic, prompt-injection 네 종류의 고정 질문 세트를 실행하고, 사전 작성한 판정 기준으로 사람이 출력의 일관성과 누설 여부를 표시한다. 모델이 자기 응답을 스스로 평가한 값은 충실성 근거로 쓰지 않는다.

## 7. 안전·개인정보 경계

- 실존 학생 데이터와 교사 기록을 사용하지 않는다.
- 이름, 학교, 학번, 성적, 대화 로그를 저장하지 않는다.
- 학생 평가, 특수교육 진단, 교사 인증 도구라고 주장하지 않는다.
- 아동이 직접 사용하는 제품이 아니라 성인 교육자용 연습 도구로 범위를 좁힌다.
- 입력은 길이 제한, 속도 제한, 프롬프트 인젝션 방어를 적용한다.
- 공개 저장소에는 제출자 주민등록번호·주소·전화번호·이메일을 저장하지 않는다.

## 8. 90초 데모 구성

1. 0~10초: “정답 15, 그럼 이해한 걸까요?” 문제 제시
2. 10~45초: 교사가 세 질문 중 두 질문을 입력, 가상 학생 답변
3. 45~60초: 숨은 오개념 선택
4. 60~75초: 정답 공개 + 대화 근거 + 후보 축소 점수
5. 75~90초: 더 강한 hinge question으로 다른 예시에서 즉시 재도전

첫 화면부터 결과 공개까지 로그인 없이 끝나야 한다.

## 9. 성공 기준

- 정답 진단 결과가 고정 정답표와 100% 일치
- 후보 축소 점수 계산이 GPT 출력과 무관하게 동일 결과를 재현
- 가상 학생이 20개 적대적 질문에서 숨은 설정을 직접 누설하지 않음
- 한 라운드의 오개념 상태가 어떤 질문에도 변경되지 않음
- 고정 probe 세트의 오개념 충실성 결과를 사람이 판정해 기록
- 핵심 흐름이 키보드만으로 동작
- 첫 방문자가 90초 안에 한 판 완료
- 실제 교사 또는 튜터 1명이 플레이하고, 첫 질문과 재도전 질문의 차이를 짧게 기록

## 10. 기존 CrossReady와의 분리

| 항목 | 기존 CrossReady | WhyRight |
|---|---|---|
| 트랙 | Work & Productivity | Education |
| 사용자 | 제출 패키지 작성자 | 교사·튜터 |
| 입력 | 규칙 문서와 ZIP | 자유 질문과 합성 수업 시나리오 |
| 핵심 경험 | 아티팩트 감사 | 가상 학생 인터뷰 게임 |
| 결과 | 근거 기반 4상태 보고서 | 오개념 진단과 후보 축소 이력 |
| GPT 역할 | 문서 의미 비교 | 일관된 반사실적 학생 시뮬레이션 |
| 화면 언어 | 감사 대시보드 | 밝고 간결한 교실형 게임 UI |

브랜드, 코드, 샘플, 영상, 디자인, 세션 ID, Git 이력을 재사용하지 않는다.
